# Q2 三主视图可行性评估与实现方案（基于 `docs/Q2.png`）

## 1. 结论（先回答“能不能做”）

可以实现。

- 视图一（轮廓对比图）：可实现，且与现有 Q2 数据结构高度匹配。
- 视图二（路径流向图）：可实现，现有接口已直接支持。
- 视图三（偏好城市地图）：可实现，但需要做“匿名稳定映射”来解决城市编码无真实地理坐标的问题。

整体判断：**可落地，风险可控，属于中等改造量**。

---

## 2. 判断依据（与现有数据/接口对应）

### 2.1 可复用接口

- `GET /api/positions/job_titles`
- `GET /api/positions/parallel`
- `GET /api/positions/sankey`
- `GET /api/positions/nested_bar`

### 2.2 可复用数据表

- `job_summary_by_title`：职位多维统计（Q2主表）
- `job_city_distribution`：职位-城市分布（地图主数据来源）
- `experience_mapping`、`education_mapping`：编码解释补充

---

## 3. 三个主视图可行性拆解

## 3.1 轮廓对比图（左）

可行性：**高**

可直接使用：
- `/positions/parallel` 四维归一化结果
- `/positions/nested_bar?detail_job=...` 补城市相关信息

本次确定维度（5维）：
1. 薪资水平
2. 技能要求
3. 行业集中度
4. 职业热度
5. 城市分布广度

## 3.2 路径流向图（中）

可行性：**高**

可直接使用：
- `/positions/sankey?mode=compare&job_titles=...`

链路保持：
- 技能水平 -> 行业分布 -> 市场需求 -> 薪资水平

## 3.3 偏好城市地图（右）

可行性：**中高（需要适配）**

可用数据：
- `job_city_distribution` 的 `city`、`job_count`（按职位聚合）

关键问题：
- 城市是脱敏编码，不能直接映射真实城市经纬度

解决方案：
- 采用“匿名稳定映射”（Deterministic Pseudo-Geo）
- 目标不是表达真实地理位置，而是表达稳定且可比较的空间分布

---

## 4. 当前风险与前置修正项

1. `job_city_distribution` 字段口径风险
- 数据库字段为：`job_count/avg_salary/avg_experience/avg_education`
- 现有部分逻辑仍按 `count/percent` 读取
- 实施前必须统一字段口径

2. 地图坐标缺失
- 无真实城市经纬度
- 需先生成并固化 `city_code -> pseudo_coord` 映射文件

3. 联动状态复杂
- 顶部同步、三图高亮、城市锁定、重置回退都需统一状态管理

---

## 5. 三主图详细实现计划（可直接开工）

## 5.1 轮廓对比图（左）详细计划

### 5.1.1 展示内容

- 三列职位卡（A/B/C）
- 五行维度评分（星级或进度条）
- 底部图例（A蓝/B红/C绿）

### 5.1.2 数据需求与口径

- 薪资水平：`parallel.values[0]`
- 技能要求：`parallel.values[1]`
- 行业集中度：`parallel.values[2]`
- 职业热度：`parallel.values[3]`
- 城市分布广度：来自每职位城市分布数据（建议口径二选一）
  - 口径A：覆盖城市数（`distinct city count`）归一化
  - 口径B：分布均衡度（基于城市岗位占比熵）归一化

建议优先：口径A（更直观，计算简单）。

### 5.1.3 交互设计

- Hover 某维度：显示原始值与归一化值
- 点击某维度：中图高亮对应层级（例如点击“技能要求”高亮技能层）
- 点击职位列头：右图仅保留该职位主色高亮

### 5.1.4 技术实现要点

- 使用统一 `viewModel.silhouette`，避免各组件自行计算
- 归一化采用全局口径，避免不同职位组合下分值漂移过大
- 颜色与职位顺序全页一致（A/B/C不变）

---

## 5.2 路径流向图（中）详细计划

### 5.2.1 展示内容

- 四层桑基路径：技能水平 -> 行业分布 -> 市场需求 -> 薪资水平
- 节点显示占比/样本量
- 连线宽度表示流量占比

### 5.2.2 数据需求

- 来源：`/positions/sankey?mode=compare&job_titles=...`
- 输入字段：`nodes[]`, `links[]`, `categories[]`

### 5.2.3 视觉编码

- 节点宽度固定，节点高度按 value
- 连线宽度按 value
- 不同层级用固定色系区分
- 支持“占比（%）/数量”显示切换

### 5.2.4 交互设计

- Hover 节点：显示节点样本量、占比、上下游
- Hover 连线：显示 source -> target、流量、占比
- 点击节点：
  - 左图高亮相关维度
  - 右图高亮相关职位颜色层

### 5.2.5 技术实现要点

- 先做 compare 模式，all 模式作为后续扩展
- 节点标签避免重叠：长标签截断 + tooltip补全
- 保留最近一次成功数据，接口失败时不清空全图

## 5.3 偏好城市地图（右）详细计划

### 5.3.1 展示内容（按你确认）

- 中国地图上各城市饼图气泡
- 饼图扇形：各职位在该城市的需求占比
- 气泡大小：总需求量

### 5.3.2 数据需求

业务数据：
- 城市编码
- 各职位在每城市岗位数量（`job_count`）

地图数据：
- 中国底图 GeoJSON
- 匿名映射坐标 `city_code -> [lng, lat]`

### 5.3.3 匿名稳定映射方案（解决编码城市上图）

1. 预生成中国范围候选点位池（建议 400~800 点）
2. 对 `city_code` 做稳定哈希（如 MD5）
3. `index = hash % N` 选点
4. 冲突时环形探测空位
5. 加确定性微抖动（由 hash 派生）
6. 固化映射文件（推荐）
- `dataset/dataset/第二题/city_pseudo_coords.json`

说明：
- 映射目标是“稳定可比较分布”，非真实城市位置。

### 5.3.4 饼图气泡聚合规则

对 A/B/C 职位按城市聚合：
- `countA`, `countB`, `countC`
- `total = countA + countB + countC`

视觉映射：
- 扇区比例：`countX / total`
- 半径：`radius = clamp(10 + k * sqrt(total), 10, 42)`

### 5.3.5 交互设计（按你确认）

- Hover：显示城市总需求及职位分布
- Click：
  - 底部薪资/经验/学历联合画像同步下钻
  - 技能面板同步下钻
  - 地图锁定当前城市并高亮

### 5.3.6 避免气泡重叠

三级策略：
1. 候选点位池生成时设最小间距
2. 映射阶段处理冲突（环形探测）
3. 渲染阶段做像素级碰撞修正（2~3轮）

补充：
- 默认仅显示 TopN 城市（如 30）可显著提升可读性

### 5.3.7 多职位对比可读性优化

- A/B/C 固定颜色且全页一致
- 图例顺序与选择器顺序一致
- Tooltip 同时显示数量和占比
- 可加“仅看职位A/B/C”开关

## 6. 三图联动总流程

1. 顶部点击“同步分析”
- 并发请求并刷新左/中/右三图

2. 左图维度点击
- 中图对应层级高亮

3. 中图节点点击
- 左图相关维度强调
- 右图相关职位层强调

4. 右图城市点击
- 底部画像与技能面板进入该城市下钻态
- 再次点击或重置退出下钻态

---

## 7. 实施顺序（推荐）

1. 统一字段口径与 viewModel
2. 完成左图5维版本
3. 完成中图路径图增强
4. 完成右图匿名映射与饼图气泡
5. 打通联动与重置
6. 完成空态/错态/性能优化

---

## 8. 验收标准

1. 可选择最多 3 个职位并同步刷新三主视图。
2. 轮廓图稳定展示 5 维：薪资水平、技能要求、行业集中度、职业热度、城市分布广度。
3. 路径图稳定展示四层链路并可交互高亮。
4. 偏好城市图在无真实城市名情况下可稳定上图。
5. Hover 可显示总需求及职位分布；点击城市可联动底部画像与技能面板下钻。
6. 常见分辨率下气泡重叠可控，不影响阅读。

---

## 9. 最终判断

**能实现，而且可以按上述计划直接推进。**

左图和中图属于直接增强；右图核心在匿名稳定映射。只要先统一城市分布字段口径，整体改造能稳定落地。
