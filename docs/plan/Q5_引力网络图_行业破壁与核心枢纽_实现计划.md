# Q5 方案三：引力网络图（Force-Directed Graph）实现计划

## 0. 结论（先回答你的问题）
你的设计是**可以且很适合答辩**的。

原因：
1. 叙事强：天然解释“为什么是新兴岗位”。
2. 结构清晰：中心岗位 + 外围行业 + 边权/边色，评委一眼能懂。
3. 与现有数据匹配：当前库里已经有岗位、行业、薪资、规模等关键字段，可直接落地。

## 1. 目标与问题定义

### 1.1 目标
构建“岗位—行业”引力网络图，回答两个核心问题：
1. 某个岗位是否跨行业渗透（是否“破壁”）？
2. 某个岗位是否是高价值枢纽（高需求 + 高薪 + 多行业连接）？

### 1.2 视图语义（沿用你的定义）
- 中心节点：新兴职位（`job_title`）
- 外围节点：关联行业（`company_type`）
- 节点大小：
  - 职位节点大小 = 该职位综合规模（岗位量）
  - 行业节点大小 = 该行业对该职位的招聘量
- 连线：职位—行业关系
  - 线宽 = 招聘数量（count）
  - 线色 = 薪资水平（暖色高、冷色低）

### 2.1 核心表与用途
| 表名 | 用途 | 关键字段 |
|---|---|---|
| `data` | 明细层，构建岗位-行业连边 | `job_title`, `company_type`, `median_annual_salary`, `min_annual_salary`, `max_annual_salary`, `city`, `city_tier`, `company` |

### 2.2 Q5 所需衍生指标
1. `edge_count(job, industry)`：岗位在某行业招聘数
2. `edge_salary(job, industry)`：岗位在该行业薪资代表值（建议中位薪资）
3. `job_total_count(job)`：岗位总需求
4. `industry_degree(job)`：该岗位覆盖的行业数（超过阈值的有效连边）
5. `industry_entropy(job)`：岗位在行业分布上的熵（越高越“破壁”）
6. `hub_score(job)`：枢纽分（融合规模、薪资、破壁性）

## 3. 新兴岗位识别口径（不依赖人工贪心命名）

> 由于当前表口径以横截面为主（时间维度有限），Q5 建议定义“新兴代理指标”，先可稳定跑通；后续若补时间字段再加入增长率。

### 3.1 单岗位评分（建议）
对每个岗位 `j` 计算：

- 规模分 `S_scale(j)`：`records_count_norm`
- 薪资分 `S_salary(j)`：`median_salary` 归一化（可融合 `q3_salary`）
- 破壁分 `S_cross(j)`：行业熵归一化（或 行业覆盖数归一化）
- 稳健分 `S_robust(j)`：`1 - std_salary_norm`（可选）

综合分：

`S_emerging(j) = 0.35*S_scale + 0.30*S_salary + 0.25*S_cross + 0.10*S_robust`

输出 Top-N 候选“新兴岗位”（如 N=20）。

### 3.2 “核心枢纽”判定
对候选岗位再算：

`Hub(j) = 0.4*industry_entropy_norm + 0.3*industry_degree_norm + 0.3*salary_norm`

用于排序与默认中心节点选择。

### 3.3 与当前 Q5“前 5 新兴职业”对齐（本次纳入）
为保证新方案与现有页面叙事连续，顶部“新兴职位速览卡片”直接复用当前 Q5 已有的前 5 职业，不重新定义一套前端候选来源。

数据来源链路：
1. 接口：`GET /api/industry/ranking/jobs`（当前后端固定 `top_n=5`）
2. 服务：`TrendService.get_job_ranking(top_n=5)`（`services/trend_service.py`）
3. 路由：`routes/industry_routes.py` 中 `/industry/ranking/jobs`
4. 前端：`fronted/src/components/tabs/Q5Tab.vue` 现有排名数据请求（`getJobRanking`）

执行口径：
- 顶部 5 张卡片即“当前 Q5 已展示的前 5 新兴职业”；
- Force 子视图默认选中该 5 个中的第 1 个作为中心节点；
- 若后续将 `top_n` 调整为更大值，顶部卡片仍只截取前 5 条展示（其余用于候选池）。

## 4. 后端实现细节

## 4.1 服务层建议
新增服务：`services/q5_force_graph_service.py`

核心方法：
1. `get_emerging_jobs(top_n=20, min_count=80)`
2. `get_job_industry_force(job_title, top_k_industry=12, city_tier='all')`
3. `get_job_hub_ranking(top_n=30)`

## 4.2 连边聚合 SQL（示例）
```sql
SELECT
  d.job_title,
  d.company_type,
  COUNT(*) AS edge_count,
  AVG(d.median_annual_salary) AS edge_salary_mean,
  PERCENTILE_CONT(0.5) WITHIN GROUP (ORDER BY d.median_annual_salary) AS edge_salary_median
FROM data d
WHERE d.job_title = %(job_title)s
  AND d.company_type IS NOT NULL
  AND d.median_annual_salary IS NOT NULL
GROUP BY d.job_title, d.company_type;
```

> 若 MySQL 版本不支持 `PERCENTILE_CONT`，改为近似中位数策略（窗口函数或离线 pandas 中位数）。

## 4.3 行业熵计算
对岗位 `j`：
- `p_i = edge_count_i / sum(edge_count)`
- `H(j) = -sum(p_i * ln p_i)`
- `H_norm = H / ln(K)`，`K` 为该岗位有效行业数

## 4.4 API 设计
新增路由：`routes/q5_force_graph_routes.py`

1. `GET /api/q5/force/emerging-jobs?top_n=20`
- 返回新兴岗位候选及分数

2. `GET /api/q5/force/job-network?job_title=xxx&top_k_industry=12&tier=all`
- 返回 force 图节点、连边、图例区间

3. `GET /api/q5/force/hub-ranking?top_n=30`
- 返回岗位枢纽排名（用于右侧榜单）

## 4.5 返回格式（前端可直接喂 ECharts）

## 5. 前端实现细节（Q5 页面）

## 5.0 网页排版（T 型结构：结论前置 + 理由剖析）
整体采用上下双区布局，建议高度比例 `3:7`（或 `4:6`）：
- 上方是“新兴职位速览卡片”（控制台），用于快速给出结论；
- 下方是“引力网络生态图”（主舞台），用于解释“为什么成立”。

### 顶部区域：新兴职位速览卡片（控制台）
1. 布局形态
- 顶部使用横向容器（`Flex` / `Grid`），并排展示 5 张职业卡片。
- 卡片统一悬浮样式，默认高亮第 1 张，其余卡片弱化（半透明或暗色）。

1.1 数据来源（明确绑定现有 Q5）
- 卡片岗位集合：直接取当前 Q5 的“前 5 新兴职业”（`/api/industry/ranking/jobs` 返回结果）。
- 卡片顺序：按现有综合分排序顺序展示（与当前 Q5 一致）。
- 兼容策略：若新 Force 接口未就绪，仍可仅依赖该 Top5 源正常展示顶部控制台。

2. 视觉焦点
- 卡片中心放置科技感抽象图标（如神经元/芯片/数据云）。
- 当前选中卡片可加呼吸灯或外发光描边，强化“当前中心岗位”状态。

3. 信息层级（图标下方）
- 指标 1：岗位需求量（映射 `records_count`），示例：`12,450 岗`。
- 指标 2：入行学历门槛（由 `avg_education_rank` 反解析标签），示例：`硕士及以上`。
- 指标 3：入行经验门槛（由 `avg_experience_rank` 反解析标签），示例：`5-10年`。

4. 交互机制
- 5 张卡片本质是单选器（radio-like）。
- 切换卡片时同步刷新底部引力图中心节点与摘要指标。
- 与现有 Q5 排名视图保持同一选择语义：选中的卡片岗位应可与原有排名视图一一对应。

### 底部区域：引力网络生态图（主舞台）
1. 画布设定
- 下半区为深色无界画布，承载当前选中职业的“行业破壁网络”。
- 中心主节点固定在画布中心，可叠加轻量力场波纹动效。

2. 节点与连线编码
- 中心恒星：当前职业节点（`job_title`）。
- 卫星星系：行业节点（`company_type`）。
- 行业节点大小：映射该行业对该岗位的需求量（`job_count` / `edge_count`）。
- 连线粗细：映射招聘记录密集度（`edge_count`）。
- 连线颜色：按薪资冷暖色映射（蓝 -> 橙红），数据取 `avg_median_salary` 或 `edge_salary`。

3. 叙事目标（答辩表达）
- 顶部卡片给出“门槛高”的结论信号（学历/经验门槛）。
- 底部引力图展示“多行业高薪争夺”的证据（暖色 + 粗线 + 多连接）。
- 形成“结论前置，证据展开”的一屏叙事闭环。

## 5.1 组件规划
在 `fronted/src/components/tabs/Q5Tab.vue` 中新增子组件：
- `Q5ForceGraph.vue`（主图）
- `Q5EmergingJobList.vue`（左侧候选职位列表）
- `Q5HubScorePanel.vue`（右侧指标说明/排名）

## 5.2 交互流程
1. 页面加载：先请求现有 `GET /api/industry/ranking/jobs`，取前 5 作为顶部卡片，默认选中第 1 个岗位。
2. 请求 `job-network`，渲染力导图。
3. 点击行业节点：右侧显示该行业对该岗位的贡献（岗位数、薪资、占比）。
4. 点击候选岗位：主图切换为新岗位网络。
5. 城市等级筛选（可选）：`tier=first_tier/second_tier/third_tier/other/all`，观察“破壁性”是否发生变化。

## 5.3 ECharts 力导图配置要点
- `series.type = 'graph'`
- `layout = 'force'`
- `force.repulsion`：行业节点 260~380，中心岗位固定 `fixed=true`
- `force.edgeLength`：按 `1/log(edge_count+1)` 映射（岗位需求越大，边越短，表示更紧密）
- 节点大小：按 value 映射，中心节点单独上限（如 60）
- 连线颜色：按 `edge_salary` 连续色带（蓝→黄→橙→红）
- 连线粗细：按 `edge_count` 映射 [1.5, 9]

## 6. 解释模板（用于答辩）

当图中出现以下模式时，可直接解释为“新兴急需”：
1. 中心岗位与多个高能行业形成粗线连接（高需求）；
2. 多条连接呈暖色（高薪认可）；
3. 行业覆盖广且分布非单峰（跨行业渗透）；
4. 在城市等级切换下仍保持多行业连接（韧性强）。

可用一句话总结：
“该岗位不是依附单一行业的局部岗位，而是多行业数字化升级共同争夺的底层能力节点。”

## 8. 风险与规避

1. 风险：`job_title`/`company_type` 为匿名编码，可解释性不足。
- 规避：保留编码展示，同时在 tooltip 强调“结构证据”而非语义名称。

2. 风险：时间维不足，难直接证明“新兴=增长快”。
- 规避：当前先用“跨行业 + 高薪 + 高需求”的代理定义；后续补时间表再加增长率指标。

3. 风险：边太多导致图拥挤。
- 规避：默认 `top_k_industry=8~12`，其余聚合为“Other”或折叠。
