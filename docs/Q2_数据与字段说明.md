# Q2 职位画像分析：现有数据与字段说明

本文用于支撑 Q2 视图设计，聚焦“当前项目已经能直接用”的数据、接口、字段与口径。

## 1. Q2 当前可用接口

- `GET /api/positions/job_titles`
  - 用途：职位选择下拉框（最多选 3 个）
- `GET /api/positions/parallel?job_titles=...`
  - 用途：职位四维对比（薪资、技能、行业集中度、热度）
- `GET /api/positions/sankey?mode=all|compare&job_titles=...&dimensions=...`
  - 用途：职位特征到薪资结果流向
- `GET /api/positions/nested_bar?job_titles=...&detail_job=...`
  - 用途：宏观对比 + 单职位下钻（含城市分布）

对应代码：`routes/position_routes.py`、`services/position_service.py`

## 2. Q2 关键数据表

## 2.1 `job_summary_by_title`（Q2 主表）

按职位汇总后的画像主数据，Q2 三个核心视图都依赖此表。

| 字段 | 类型 | 含义 | Q2 用途 |
|---|---|---|---|
| `job_title` | varchar | 职位标识/名称 | 选择器、各视图主键 |
| `records_count` | varchar | 职位样本量 | 热度维度、排序 |
| `min_salary` / `q1_salary` / `median_salary` / `q3_salary` / `max_salary` | varchar | 薪资分布分位 | 薪资维度、箱线/区间展示 |
| `std_salary` | varchar | 薪资波动 | 可作为稳定性指标 |
| `avg_experience_rank` | varchar | 平均经验等级分值 | 技能/门槛刻画 |
| `avg_education_rank` | varchar | 平均学历等级分值 | 技能/门槛刻画 |
| `total_shannon_entropy` | varchar | 行业分布熵 | 行业集中度（通常取反） |
| `skill_score` | varchar | 技能综合分 | 技能要求维度 |
| `skill_level` | varchar | 技能等级（初/中/高） | 桑基第一层维度 |
| `industry_spread` | varchar | 行业分散等级 | 桑基维度 |
| `market_demand` | varchar | 市场需求等级 | 桑基维度 |
| `salary_level` | varchar | 薪资等级 | 桑基结果层 |

说明：该表字段多数为字符串，服务层已做 `CAST/float/int` 处理。

## 2.2 `job_city_distribution`（职位-城市分布）

用于职位偏好城市、Top 城市摘要、下钻城市信息。

| 字段 | 类型 | 含义 | Q2 用途 |
|---|---|---|---|
| `job_title` | varchar | 职位 | 与主表关联 |
| `city` | varchar | 城市编码 | 城市偏好分布 |
| `job_count` | bigint | 该职位在该城市岗位数 | 气泡大小/条形长度 |
| `avg_salary` | double | 城市内该职位平均薪资 | tooltip/细节 |
| `avg_experience` | decimal | 城市内经验均值 | tooltip/细节 |
| `avg_education` | decimal | 城市内学历均值 | tooltip/细节 |

## 3. 各视图的数据口径（按当前实现）

## 3.1 平行坐标图（`/positions/parallel`）

- 维度固定 4 个：
  - 薪资待遇：`median_salary` 归一化（并剔除全局最高两个异常值）
  - 技能要求：`skill_score` 归一化
  - 行业集中度：`100 - normalize(total_shannon_entropy)`
  - 职业热度：`records_count` 归一化
- 返回结构：
  - `dimensions: [..]`
  - `positions[].values`（0-100）
  - `positions[].details`（薪资、经验、学历、熵、频次）

## 3.2 桑基图（`/positions/sankey`）

- 输入维度可选：`skill_level`、`industry_spread`、`market_demand`
- 输出结果层固定是 `salary_level`
- 支持 `mode=all`（全局）和 `mode=compare`（选中职位）
- 返回结构：`nodes`、`links`、`categories`

## 3.3 嵌套柱状图（`/positions/nested_bar`）

- 第一层 `macro_comparison`：
  - `skill_score`（由经验+学历加权计算）
  - `industry_concentration`（由熵反向）
  - `avg_salary`、`records_count`
- 第二层 `micro_analysis`（有 `detail_job` 时）：
  - `salary_statistics`（min/q1/median/q3/max/avg）
  - `top_cities` + `all_cities`
  - `comparison_with_all`（全体均值/百分位）

## 4. 设计 Q2 时要注意的现实约束

- 当前没有“技能词级别明细表”（如 Python/SQL/Java 一行一词），只有 `skill_score/skill_level` 聚合值。
- 城市字段目前多为编码（如 `S542`），若要中国地图直出，需要城市编码映射表（编码 -> 中文名/经纬度）。
- 行业字段 `company_type` 为编码型值（如 `type_xxx`），需要可读化映射时应补字典表。

## 5. 视图设计建议（基于现有数据可立即落地）

- 先做“可落地版”：
  1. 四维平行坐标（可附加两维代理指标）

- 再做“增强版”：
  1. 技能词共现图谱（需新增 `job_skill` 类明细表）
  2. 真地图饼气泡（需城市编码映射）
  3. 行业中文标签映射
