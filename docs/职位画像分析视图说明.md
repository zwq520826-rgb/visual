# Q2 职位画像分析视图说明

## 1. 任务定位

Q2 当前页面对应“职位画像分析”。它面向最多 3 个职位做并行比较，把职位轮廓、路径关系和城市偏好组织成一张统一工作台，回答“这些职位各自是什么样、差异体现在什么地方、偏好落在哪些城市”。

当前实现入口为 `fronted/src/components/tabs/Q2Tab.vue`。与旧文档中提到的“平行坐标图 + 嵌套柱状图”不同，当前真实页面已经改成“轮廓对比图 + 桑基图 + 偏好城市地图”的三主视图结构。

## 2. 页面总览

- 页面分为四层：
  - 顶部 Hero 标题区
  - 职位选择与动作区
  - 三主视图工作区
  - 底部统计条
- 三主视图并排展示：
  - 左：轮廓对比图
  - 中：路径流向图
  - 右：偏好城市地图
- 右侧地图面板内部还嵌入了城市锁定摘要、图例筛选和城市下钻信息区。

## 3. 页面控制与核心状态

- 职位选择区提供三个统一选择器，对应职位 A、B、C。
- `同步分析` 是当前页面最重要的动作按钮。点击后会并发触发：
  - 职位画像主数据请求
  - 桑基图数据请求
  - 城市偏好分布数据整理
- `重置` 会清空统一选择、视图状态和地图选中状态。
- 页面核心状态包括：
  - `unifiedJobs`
  - `selectedJobs`
  - `sankeyJobs`
  - `sankeyMode`
  - `selectedCityCode`
  - `activeMapSlots`
  - `mapViewConfig`

## 4. 视图 A：轮廓对比图

### 4.1 位置与职责

- 位置：三主视图区域左侧。
- 职责：作为职位画像的第一层摘要，对最多 3 个职位做多维轮廓对比。

### 4.2 视觉与编码方式

- 当前不是传统雷达图，而是卡片式“轮廓矩阵”。
- 上方先显示职位 A/B/C 的头像卡片、简称和综合强度条。
- 下方按维度逐行展示能量条矩阵，每个职位在每一维上以分段亮度表示强弱。

### 4.3 数据与字段

- 数据来自 `getParallelCoordinatesData(jobTitles)`，接口路径为 `/positions/parallel`。
- 当前轮廓图使用的五个对比维度是：
  - 薪资水平
  - 技能要求
  - 行业集中度
  - 职业热度
  - 城市分布广度
- 其中前四项来自接口返回的 `positions[].values`，城市分布广度来自父组件单独计算的 `cityBreadthScores`。

### 4.4 数据流

- 用户选中职位后点击“同步分析”，父组件才真正把 `selectedJobs` 固化并请求数据。
- 请求返回后，父组件把 `chartData?.data` 和 `cityBreadthScores` 传给 `Q2SilhouetteComparisonChart`。

### 4.5 交互与联动

- 该视图不负责反向筛选，主要承担总览解释。
- 同步分析后，它和桑基图、地图共享同一组职位上下文。

### 4.6 状态与限制

- 加载中显示“正在加载轮廓数据...”。
- 如果没有职位选择，则显示“请选择职位后点击同步分析”。
- 最多只显示前三个职位槽位，空槽位以占位卡形式保留布局。

### 4.7 实现备注

- 组件路径：`fronted/src/components/charts/Q2SilhouetteComparisonChart.vue`
- 虽然 API 名仍叫 `getParallelCoordinatesData`，但当前前端已经把它消费成轮廓矩阵，而不是旧版平行坐标图。

## 5. 视图 B：路径流向图

### 5.1 位置与职责

- 位置：三主视图区域中部。
- 职责：解释职位特征如何流向行业、需求和薪资结果，是 Q2 中偏“关系机制”的视图。

### 5.2 视觉与编码方式

- 使用桑基图编码路径流量。
- 面板头部提供模式切换：
  - `整体模式`
  - `对比模式`
- 标题下方会同步显示当前模式的说明文案。

### 5.3 数据与字段

- 数据来自 `getSankeyData(mode, jobTitles, dimensions)`，接口路径为 `/positions/sankey`。
- 当前默认维度链保存在 `selectedDimensions`：
  - `skill_level`
  - `industry_spread`
  - `market_demand`
- 组件真实使用的数据结构是：
  - `nodes`
  - `links`

### 5.4 数据流

- 当点击“同步分析”时，父组件会按当前 `sankeyMode` 和已选职位请求桑基图数据。
- `all` 模式下可只看全局结构。
- `compare` 模式下会把职位数组一并传给接口。

### 5.5 交互与联动

- 桑基图与另外两张主图共享同一组职位输入。
- 模式切换本身会改变数据请求口径，而不是只切换前端样式。

### 5.6 状态与限制

- `all` 模式空态提示是“点击【同步分析】加载整体模式路径图”。
- `compare` 模式空态提示是“选择职位后点击【同步分析】”。
- 加载和报错状态分别由 `sankeyLoading` 与 `sankeyError` 控制。

### 5.7 实现备注

- 组件路径：`fronted/src/components/charts/SankeyChart.vue`
- 父层使用 `SANKEY_JOB_COLORS` 维护职位颜色语义，保证与其它区域的一致性。

## 6. 视图 C：偏好城市地图

### 6.1 位置与职责

- 位置：三主视图区域右侧。
- 职责：展示不同职位在全国城市中的需求分布，并支持单城市下钻。

### 6.2 视觉与编码方式

- 底图为全国地图，移除了南海诸岛插图以扩大主体区域。
- 每个城市标记不是单色圆点，而是三职位的复合标记，体现 A/B/C 槽位在该城的占比。
- 地图面板提供大量视图微调控制：
  - 容器宽度
  - 容器高度
  - 地图大小
  - 缩放
  - 宽高比
  - 中心点
- 同时支持按钮式放大、缩小、平移和复位。

### 6.3 数据与字段

- 地图基础数据不是直接由单个接口返回，而是父组件根据职位主数据二次加工得到 `cityPreferenceMarkers`。
- 组件实际使用的城市标记字段包括：
  - `code`
  - `mappedLon`
  - `mappedLat`
  - `counts`
  - `ratios`
  - `total`
  - `rank`
- 地图还依赖城市锚点配置：
  - `CHINA_CITY_ANCHORS`
  - `HOT_CITY_PRIORITY`

### 6.4 数据流

- “同步分析”后，父组件会把职位数据转换成地图标记数组。
- 标记数组传入 `Q2CityPreferenceGeoMap` 后，由组件内部完成布局、防重叠和地图缩放适配。
- 当前地图选中城市会回写到 `selectedCityCode`。

### 6.5 交互与联动

- 点击城市标记可锁定或取消锁定城市。
- 图例支持按职位槽位过滤：
  - 仅看 A
  - 仅看 B
  - 仅看 C
  - 或全部同时看
- 地图视角变化会通过 `view-change` 事件同步回父组件，更新滑杆值。

### 6.6 状态与限制

- 加载中显示“正在计算城市偏好分布...”。
- 没有标记数据时显示“选择职位后点击【同步分析】生成偏好城市图”。
- 城市名称当前采用匿名编码展示，界面右上角有明确提示。

### 6.7 实现备注

- 组件路径：`fronted/src/components/charts/Q2CityPreferenceGeoMap.vue`
- 当前地图不是传统行政区着色图，而是“匿名城市点位 + 比例复合标记”的空间分布图。

## 7. 视图 D：城市锁定摘要与下钻信息区

### 7.1 位置与职责

- 位置：地图主画布下方和右下延展区。
- 职责：当用户锁定城市后，对该城市做局部解释，是地图视图的细粒度补充。

### 7.2 视觉与编码方式

- 第一层是 `city-summary-box`，展示锁定城市的简要摘要。
- 第二层是 `city-drilldown`，按职位 A/B/C 三格卡片展示：
  - 当前城市需求量
  - 当前城市占比
  - 薪资
  - 经验
  - 学历

### 7.3 数据与字段

- 摘要依赖 `selectedCitySummary`，字段包括：
  - `code`
  - `mappedLon`
  - `mappedLat`
  - `total`
  - `counts`
  - `rank`
- 下钻信息结合：
  - 地图标记摘要
  - `chartData.data.positions[].details`

### 7.4 数据流

- 用户点击城市标记后，父组件从 `cityPreferenceMarkers` 中查找对应条目生成 `selectedCitySummary`。
- 再结合职位详情构造 `selectedCityJobProfiles`，作为下钻卡片的数据源。

### 7.5 交互与联动

- 该区域完全跟随地图选中城市变化。
- 不单独反向控制三主视图。

### 7.6 状态与限制

- 没有选中城市时，这部分区域不渲染。
- 主导职位标签是根据三职位在该城市中的最大计数计算得到的。

### 7.7 实现备注

- 这部分不是独立组件，而是 `Q2Tab.vue` 内直接渲染。
- 它是当前实现中最接近“地图下钻面板”的区域。

## 8. 视图 E：底部统计反馈条

### 8.1 位置与职责

- 位置：页面底部。
- 职责：给当前这轮同步分析一个总体数据范围摘要。

### 8.2 视觉与编码方式

- 采用四格统计卡条，展示：
  - 分析样本
  - 覆盖行业
  - 覆盖城市
  - 分析维度

### 8.3 数据与字段

- `分析样本` 来自 `chartData.data.positions[].details.job_frequency` 汇总。
- `覆盖行业` 来自桑基图 `nodes` 中 `category === '行业分布'` 的节点数量。
- `覆盖城市` 来自地图标记数组长度。
- `分析维度` 当前写死为 `5 大维度`。

### 8.4 数据流

- 统计条不独立请求数据，而是复用三主视图已拿到的数据。

### 8.5 交互与联动

- 仅展示，不反向驱动其它视图。

### 8.6 状态与限制

- 如果主数据尚未加载完成，部分统计值会暂时为 `0` 或空值。

### 8.7 实现备注

- 这部分仍然写在 `Q2Tab.vue`，没有拆出单独组件。

## 9. 联动与状态流

- 统一职位选择 -> 点击“同步分析” -> 三主视图和统计条同时更新。
- 地图点击城市 -> 更新城市摘要与下钻区。
- 地图槽位图例切换 -> 只影响地图展示集合，不改变轮廓图和桑基图数据。
- 地图视角操作 -> 回写 `mapViewConfig`，保持控件与当前视图一致。
