# Q1 视图实现说明

## 1. 任务定位

Q1 当前页面对应“职位差异度分析”。页面以职位为基本观察单元，通过一个主视图加两个辅助视图，回答“职位之间差在哪里、差异由哪些维度构成、哪些职位值得并行比较”这类问题。

当前实现入口为 `fronted/src/components/tabs/Q1Tab.vue`。页面主容器负责承接散点图中的选中职位，再把选中结果同步给右侧雷达图和蝴蝶图。

## 2. 页面总览

- 页面结构是典型的 `左主右辅` 双栏布局。
- 顶部 `Hero` 区展示任务标题、说明，以及三个状态型指标：已选职位数、雷达图需求数量、蝴蝶图需求数量。
- 左侧主面板承载散点气泡图，负责职位选择与维度切换。
- 右侧分上下两个面板，分别放置雷达对比图和蝴蝶差异图。
- `Q1Tab` 本身不直接请求图表数据，而是通过组件引用读取散点图内部的 `selectedNodes`，用轮询方式同步状态。

## 3. 页面控制与核心状态

- 选中状态来源于 `ScatterBubbleChart` 暴露的 `selectedNodes`。
- `Q1Tab` 在挂载后每 `300ms` 轮询一次散点组件，将已选职位同步到 `selectedNodes`。
- 页面没有额外的全局“同步分析”按钮，交互入口就是散点图点击。
- 右侧两个图不维护独立选择状态，完全以左侧传入的职位数组为准。

## 4. 视图 A：职位散点矩阵

### 4.1 位置与职责

- 位置：页面左侧主面板。
- 职责：作为 Q1 的主交互入口，负责展示职位分布，并驱动后续对比分析。

### 4.2 视觉与编码方式

- 使用 ECharts 散点/气泡编码。
- 横轴和纵轴支持多指标切换，默认是 `平均经验` 与 `平均薪资`。
- 气泡大小支持切换，默认使用 `job_in_city_cnt`。
- 当前公开视图模式是“城市 · 职位层级”，图例按职位层级上色。
- 支持 `Top 标注` 开关，用于高亮头部职位。

### 4.3 数据与字段

- 城市列表来自 `getRepresentativeCities()`，接口路径为 `/q1/cities`。
- 城市散点数据来自 `getScatterData(city)`，接口路径为 `/q1/scatter`。
- 组件中真实使用的核心字段包括：
  - `job_title`
  - `avg_salary`
  - `avg_experience`
  - `avg_education`
  - `job_in_city_cnt`
  - `salary_std`
  - `avg_shannon_entropy`
- 组件内部还保留全国行业散点分支 `getNationalIndustryScatter()`，但当前页面没有暴露切换入口。

### 4.4 数据流

- 组件挂载时先请求代表性城市列表。
- 若城市列表存在，默认选中第一个城市并请求该城市散点数据。
- 用户切换城市或维度后，图表会重新计算坐标、气泡尺寸和类别显隐。
- 当前选中职位存储在组件内部 `selectedNodes`，供 `Q1Tab` 读取。

### 4.5 交互与联动

- 点击气泡可加入或更新“已选职位”集合。
- 点击图例项可做类别显隐过滤。
- 点击“清除选择”会清空当前已选职位，并触发右侧两个图恢复提示态。
- 该视图是 Q1 唯一的数据选择入口，右侧两个视图都被它驱动。

### 4.6 状态与限制

- 城市模式下若没有选中城市，不会请求散点数据。
- 若无已选职位，右侧雷达图和蝴蝶图进入空态提示。
- 当前实现没有在散点图层面对选择数量做硬限制，但右侧图表会按自己的规则决定是否渲染。

### 4.7 实现备注

- 组件路径：`fronted/src/components/charts/ScatterBubbleChart.vue`
- 关键 API：`fronted/src/api/q1Api.js`
- 当前文案称其为“职位散点矩阵”，但实际编码主体是单画布散点气泡图，不是多子图矩阵。

## 5. 视图 B：职位多维对比雷达图

### 5.1 位置与职责

- 位置：页面右上辅助面板。
- 职责：对已选职位做多维轮廓比较，快速判断职位的相对强弱和结构差异。

### 5.2 视觉与编码方式

- 使用 ECharts 雷达图。
- 每个职位一条独立轮廓线，默认使用蓝、红、浅蓝等颜色区分。
- 图中心位于容器中下部，顶部额外放置标题和图例。
- 每个维度都被标准化到 `0-100` 区间，便于同屏比较。

### 5.3 数据与字段

- 输入直接来自父组件传入的 `selectedJobs`。
- 使用的六个对比维度是：
  - `avg_salary`
  - `avg_experience`
  - `avg_education`
  - `job_in_city_cnt`
  - `salary_std`
  - `avg_shannon_entropy`
- Tooltip 中会展示每个职位的真实值，而不是只显示标准化结果。

### 5.4 数据流

- `Q1Tab` 将散点图选中的职位数组传入 `RadarComparisonChart`。
- 组件在每次收到新数组后重新计算当前数据集的范围，并做动态归一化。
- 如果某个维度在当前对比集合中 `max≈min`，组件会自动加 padding，避免绘制成一条直线。

### 5.5 交互与联动

- 该视图不反向控制其他视图，只承担展示角色。
- 当用户继续在散点图中增删职位时，雷达图会自动更新对比集合。
- Tooltip 是主要交互，用于查看真实数值。

### 5.6 状态与限制

- 当 `selectedJobs.length === 0` 时显示提示文案。
- 页面文案推荐选择 `2-3` 个职位；组件层没有强制阻止超过 3 个，但当前页面通常只围绕少量职位做比较。

### 5.7 实现备注

- 组件路径：`fronted/src/components/charts/RadarComparisonChart.vue`
- 标题是“职位多维对比”，指标名称固定，不跟随散点图的轴切换而变化。

## 6. 视图 C：差异度分解（蝴蝶图）

### 6.1 位置与职责

- 位置：页面右下辅助面板。
- 职责：对两个职位做镜像对比，并突出每个维度的差异贡献占比。

### 6.2 视觉与编码方式

- 使用左右镜像条形图。
- 左侧职位使用蓝色，右侧职位使用红色。
- Y 轴分类名称中直接拼接“差异贡献占比”，把维度标签与贡献值合并展示。
- 顶部通过 `graphic` 文本额外强调“差异度贡献占比”。

### 6.3 数据与字段

- 输入同样来自父组件传入的 `selectedJobs`。
- 使用的六个维度与雷达图一致：
  - `job_in_city_cnt`
  - `avg_salary`
  - `avg_experience`
  - `avg_education`
  - `salary_std`
  - `avg_shannon_entropy`
- 每个维度会先计算两个职位的相对差值，再归一化为贡献占比。

### 6.4 数据流

- 当且仅当传入数组长度为 `2` 时初始化图表。
- 数据构造过程会同时生成：
  - 左右两侧镜像柱长度
  - 原始真实值
  - 每个维度的差异贡献百分比

### 6.5 交互与联动

- 该图不负责反向联动。
- 主要交互是 Tooltip，显示左右职位真实值和该维度差异贡献。
- 用户重新选择职位后，蝴蝶图会重新构造全部维度并刷新。

### 6.6 状态与限制

- 少于 2 个职位时显示“请选择 2 个职位查看真实值对比”。
- 多于 2 个职位时显示“蝴蝶图仅支持 2 个职位”。
- 因此它是 Q1 中限制最严格的视图。

### 6.7 实现备注

- 组件路径：`fronted/src/components/charts/JobDifferenceButterflyChart.vue`
- 图中的条形长度不是原始值，而是按当前维度两职位的相对最大值归一后的镜像长度，真实值通过标签和 Tooltip 补充。

## 7. 联动与状态流

- 主状态链路是：`ScatterBubbleChart.selectedNodes -> Q1Tab.selectedNodes -> RadarComparisonChart / JobDifferenceButterflyChart`。
- Q1 的联动属于“单入口、双下游”模式：
  - 一个职位集合可驱动雷达图的多目标比较。
  - 同一集合在数量等于 2 时可触发蝴蝶图的双目标差异分析。
- 页面没有复杂的反向刷选逻辑，保证了实现简单且认知路径清晰。
